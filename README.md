### 【アピールプロダクト】AI Carbon Calculator（炭素排出量可視化・AI削減提案アプリ）
- **公開URL**：https://ai-carbon-calculator.vercel.app

### 1. 開発背景や課題（なぜ開発しようと思ったかという理由）
近年、世界的な気候変動対策や企業のESG経営、個人のエコ意識の高まりに伴い、「自らの活動からどれだけの温室効果ガス（CO2）が排出されているか」を把握することへの重要性が急速に増しています。しかし、従来の算出ツールや専門機関の報告書は計算式や単位が難解であり、入力項目も複雑なため、一般の生活者や中小企業が気軽に実態を把握し、具体的な行動に移すには高いハードルがありました。

私自身、Evercomm SingaporeにおいてIoTエネルギー分析ダッシュボードの開発に携わった経験から、「専門知識がなくても、日常的な数値（移動距離・電気使用量・食生活など）を入力するだけで瞬時に排出量がわかり、さらに最新の生成AIがその人の生活・事業に合わせた実効性の高い削減アクションを提案してくれるツールがあれば、環境負荷低減に向けた具体的な第一歩を後押しできるのではないか」と考え、本プロダクトの開発を決意しました。

### 2. 開発における役割（担当工程）
企画立案からデータモデリング、UI/UXデザイン、フロントエンド実装（HTML/CSS/JavaScript）、AIプロンプトエンジニアリング、非同期通信制御、Vercelによるデプロイ・公開まで、**全工程を個人で単独完遂**しました。

実務現場で培った「ユーザー目線の使いやすさ」「保守性の高いクリーンなコード設計」「エラー発生時にも破綻しない堅牢な非同期処理」を個人開発でも徹底して実践しました。

### 3. プロダクトを作る上で技術的にこだわった点や工夫した点（ユーザーへの価値最大化）
- **① 外部ライブラリに依存しない軽量なVanilla JavaScript設計による即時計算エンジン**  
  ユーザーに入力ストレスを感じさせないため、あえて重厚なフレームワークに頼らず、純粋なHTML5/CSS3/JavaScript（ES6+）で実装しました。これにより、バンドルサイズを極限まで軽量化し、初回ロード時間をサブセカンド（1秒未満）に抑えています。また、ユーザーがフォーム数値を変更した瞬間に、イベントリスナーを通じてリアルタイムに排出量とカテゴリ別内訳が再計算されるリアクティブな計算ロジックを独自設計しました。
- **② 生成AI APIとの非同期通信とプロンプトエンジニアリング（安定したJSON構造化出力）**  
  AIからの削減アドバイスを自然言語のまま受け取ると、文章のブレや表示崩れの原因となります。そこで、AIへのプロンプト設計において「削減アクション名」「期待される削減量（kg-CO2/年）」「難易度・優先度」「具体的なアドバイス理由」を厳格なJSONスキーマとして出力させるプロンプトエンジニアリングを工夫しました。非同期通信（Fetch API / async-await）を用いてAIの回答を確実にパースし、直感的なアドバイスカードとしてグラフィカルに描画する仕組みを構築しました。
- **③ 専門知識不要で直感的に理解できるUI/UXと視覚的フィードバック**  
  環境問題という専門性の高いテーマだからこそ、数値を入力する楽しさを感じてもらえるUIを追求しました。排出量の大小に応じて色（安全圏のグリーン〜注意のレッド）が動的に変化するビジュアルフィードバックや、カテゴリ別（交通・エネルギー・食生活）の割合を示す視覚的なバーをCSSで実装しました。また、スマートフォンからでも親指一本で迷わず操作できるよう、タッチ領域の広い入力フィールドとレスポンシブデザインを徹底しています。
- **④ ネットワーク障害やAPIレート制限に備えたエラーハンドリング**  
  外部のAI API通信時に万が一遅延やエラーが発生した場合でも、画面全体がフリーズすることのないよう、適切なローディングスピナーの表示と`try-catch`によるフォールバック処理を実装しました。API通信失敗時には、あらかじめ用意したオフライン用の標準削減ガイドラインを表示することで、ユーザー体験を一切損なわない堅牢性を確保しています。

### 4. まとめ（選考企業様へのアピール）
本プロダクトの開発を通じて、単にWeb技術を使いこなすだけでなく、「社会的な課題に対して、ITと生成AIを掛け合わせて誰でも使える実用的なサービスへと形にする推進力」を培うことができました。3年以上の実務経験で培った基礎技術力と自走力を活かし、貴社の開発現場においてもユーザー価値を最大化するプロダクト開発に即戦力として貢献いたします。

## 【設問3】ご自身の感じているソフトウェアエンジニアとしての課題および、現在その課題に対してどのような行動を取られているか教えてください。

### 1. ソフトウェアエンジニアとして感じている課題
私が現在、ソフトウェアエンジニアとして最も成長の余地（課題）を感じている点は大きく2点あります。

1点目は、**「大規模トラフィックや可用性を支えるクラウドインフラ（AWS/GCP/Docker等）およびDevOps・分散システム設計の深化」**です。これまでReact/Next.jsを中心としたフロントエンド開発や、Java Spring BootによるREST API実装を強みとしてきましたが、より大規模な商用サービスを安定稼働させるためのコンテナ環境運用、CI/CD自動化パイプライン、データベースのインデックス・クエリチューニングなどのインフラ領域において、さらなる実践知と設計力を身につける必要があると考えています。

2点目は、**「要件定義など上流工程におけるビジネス視点と、日本語での高度な提案力・合意形成力」**です。仕様書の理解や日々の報連相（JLPT N2）は円滑に行えますが、単に指示された機能を実装するだけでなく、クライアントや非エンジニアのステークホルダーに対しても「なぜその設計が事業成長やユーザー体験につながるのか」を論理的かつ分かりやすく日本語で提案・合意形成する力をさらに高めたいと感じています。

### 2. 課題に対する現在の行動と学習内容
これらの課題を克服するため、現在以下の具体的な行動を継続して取っています。

- **クラウド・コンテナ・CI/CDの実践導入**:  
  個人開発プロダクトにおいてDockerを用いた開発環境のコンテナ化を実践し、GitHub Actionsによる自動テスト・デプロイ環境を構築しています。また、東京IT専門学校での授業や公式ドキュメントを通じて、AWS（ECS, Lambda, RDS, S3）のアーキテクチャ設計やリレーショナルDBのインデックス最適化を体系的に学習しています。
- **ビジネス日本語と技術的ディスカッション力の強化**:  
  専門学校でのチーム制作やプレゼンテーションにおいて、技術的なトレードオフ（パフォーマンス、開発工数、保守性）を言語化し、相手に納得してもらう説明を意識して実践しています。また、より自然で格調高い日本語運用を目指して上位資格であるJLPT N1レベルの語彙・読解学習を並行して進めています。

### 3. 今後のキャリアプラン
- **短期（入社1〜2年目）**:  
  即戦力のフルスタックWebエンジニアとして、React・Next.js・Java・データベースの技術をフルに活かし、高い実装スピードと品質でチームの開発目標達成に貢献します。日本の職場文化に素早く馴染み、誠実な報連相を通じてチームメンバーから厚い信頼を得ることを目指します。
- **中期（3〜5年目）**:  
  インフラからフロントエンドまでを一気通貫で見通せる**テックリード（Tech Lead）**へ成長し、新規機能の要件定義や非機能要件（セキュリティ・パフォーマンス・スケーラビリティ）の設計を牽引します。
- **長期（5年以降）**:  
  技術とビジネスの両輪を理解する**フルスタックアーキテクト／ブリッジエンジニア**として、チームの技術力向上を牽引しながら、企業の新規事業やグローバル展開を技術の力で力強くリードできる人材を目指します。
